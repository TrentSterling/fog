HOW IT WORKS

Motion and rendering are separate choices.

The motion model decides how a wake evolves. The renderer turns that result into visible fog. Any motion model can drive any renderer, so you can compare one choice while holding the other steady.

How does the fog move?

Analytical
Rebuilds disturbances from recent paths. Wakes fade with age; no simulation texture or pressure solve is needed.
Hybrid
Keeps a small texture of velocity, density, and wake energy. Each update moves the contents and adds new interactions.
GPU fluids
Solves pressure to reduce divergence, with obstacle boundaries and vorticity confinement, using texture passes.
CPU fluids
Runs the same kind of pressure solve in JavaScript typed arrays, then uploads a density and velocity texture to the shared renderer.

How do we draw it?

Mesh
One gently displaced sheet, or four shells. Texture opacity and soft depth intersections suggest a thicker bank.
Raymarch
Samples density along the view ray through a shallow volume. More work per pixel, with softer depth and silhouettes.
Layered
Combines the two: 30% of the optical density budget goes to the mesh and 70% to the volume.

All modes share the world, interaction inputs, and fog appearance controls. Analytical motion reconstructs its result from history; the CPU and GPU solvers read a stored field. The grid stores horizontal flow and concentration, not a full 3D simulation.

Changing experiments or restoring a view restarts the simulation. A shared link stores settings and camera, not the current texture or elapsed time. Timings include every visible pane, so use Solo when measuring performance.

What this experiment does not simulate

The flow is horizontal and two dimensional. Rock footprints and optional pillars are solid grid boundaries. Hills change visible fog height but are not flow barriers. Analytical motion only excludes the obstacle mask; Hybrid has no pressure solve. This is not a 3D buoyancy simulation. These are original approaches to the effect, not a verified description of Nintendo's implementation.

FOGLAB / FIELD NOTES

One world. CPU and GPU flow.

This file contains Three.js, shaders, geometry, and a generated, seamless noise atlas. Open it directly in a WebGL 2 browser. The baked noise atlas stays static. In Hybrid and Stable fluids, the density texture carries the broad cloud shapes as it moves; restrained noise adds edge detail. The default neutral stage makes gaps and wakes easy to inspect.

The motion models

Analytical

Up to 24 decaying trail stamps reconstruct density, motion, and wake energy from position history. The chosen renderer uses that result for a surface or volume. There is no simulation texture and no pressure solver.

Hybrid

A low-resolution ping-pong texture retains velocity, density, and wake energy. One update advects, fades, and adds interaction. It does not solve incompressibility.

GPU fluids

A real GPU solver advects velocity, adds interaction and vorticity, computes divergence, iterates a Jacobi pressure solve, projects velocity, and transports density. This is a horizontal 2D field, reconstructed below a shared fog ceiling. Terrain can rise above the fog.

CPU fluids

A JavaScript typed-array solver performs advection, confinement, pressure projection, and density recovery on the CPU. The result uploads to the same renderer. Start with 64²; this runs on the main thread, and large grids can reduce responsiveness.

Choose how to see it

Mesh uses deformed fog surfaces, transported cloud density, and soft scene-depth intersections. Raymarch integrates the same field through a shallow volume. Layered divides the fog budget between an ambient mesh and a reactive volume. These are interchangeable rendering choices, independent of the motion model.

What the numbers mean

The GPU timer measures the full current frame, including the shared scene and every visible pane, when timer-query support is available. Otherwise the UI reports CPU frame time including simulation and draw submission, which is not GPU time. Simulation runs at a fixed 30 Hz; frame rate and GPU milliseconds are live measurements from this device. CPU mode separately reports solve plus packing time per tick and scheduled texture upload bytes, excluding GPU transfer time. It uses zero GPU simulation passes but still renders on the GPU. These numbers do not predict Quest performance. WebXR is not implemented.

Research & credits

This is an original experiment inspired by reactive ground fog. It is not a confirmed reconstruction of Nintendo's implementation. A single horizontal field does not simulate full 3D buoyancy or general obstacle flow. Rock footprints and optional pillars now form static, grid-aligned fluid boundaries. They approximate the meshes rather than collide with every triangle. The fog ceiling clips against hills; the horizontal velocity solve itself does not include the hills as obstacles.
